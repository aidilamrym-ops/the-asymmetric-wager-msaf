6.6 FIVE DEFECTS FOUND BY EXECUTION, FIXED BEFORE THE CERTIFICATE WAS TRUSTED
  1. missing .abs() on the python-flint ball (destroyed a finished build).
  2. symmetry test mathematically wrong: it compared A[i,j] == A[j,i], but on a
     ball x-x = [0 +/- 2r] is never empty, so a PERFECTLY SYMMETRIC matrix would
     have produced a false ASYMMETRIC signal -- a manufactured falsification.
     Replaced by mutual containment (a.contains(b) and b.contains(a)).
  3. Lf[i][i] left at zero when materialising L, making arb_mat.inv() report
     "matrix is singular" and costing the whole lambda_min bound.
  4. anomaly hard-coded False in the escalation-exhausted branch, with anomalies
     overwritten by the undetermined message: a certified NEGATIVE pivot would
     have been silently swallowed -- the worst failure mode a falsification
     engine can have.  Fixed: anomalies is re-initialised per attempt and
     anomaly = bool(anomalies); undetermined is reported separately through
     non_result_reason.
  5. missing non_result key in the certified branch of the result schema.

6.7 python-flint 0.9.0 API FACTS, MEASURED (not assumed)
  * no .abs() on the ball type; abs_lower() / abs_upper() are the rigorous
    primitives (abs_lower returns 0 on a ball containing 0, so a bound degrades
    instead of overclaiming).
  * == and != both return False EVEN FOR A BALL COMPARED WITH ITSELF when the
    radius is nonzero -- hence mutual containment rather than equality.
  * .contains(), .upper(), .lower(), .sqrt(), .str(n, radius=False) and
    arb_mat.inv() behave as expected; inv() requires a unit diagonal.
